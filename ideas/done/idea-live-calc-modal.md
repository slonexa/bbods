# Идея: Live-режим для модалки "Расчёт" (точечная живая котировка перед входом)

**Приоритет: средний — не блокирует текущую работу, но недорогая и полезная фича, когда дойдут
руки. Не требует переделки основной таблицы.**

---

## Проблема, которую решает

Коэффициенты (особенно на Bybit Odds) естественно и довольно резко меняются в реальном времени —
это не баг (см. раздел ниже), а нормальная механика фикс-прайс контракта, который постоянно
переоценивается как живой бинарный опцион (чем ближе к экспирации, тем быстрее). Из-за этого
между моментом "увидел интересный спред в таблице" и моментом "реально кликнул по обеим ногам"
цифры могут успеть уйти — то, что видно в модалке "Расчёт", это снепшот из базы на момент
последнего цикла сбора, не гарантированно то, что будет доступно прямо сейчас.

## Почему это НЕ баг и не то же самое, что Frozen Cache

Важно не путать с багом устаревших данных (4 случая Frozen Cache, уже пофикшены). Там данные
были **мёртвыми**, но выдавались за живые. Здесь данные **живые и честные**, просто рынок
объективно движется быстрее, чем цикл обновления таблицы/пауза между "увидел → кликнул".
Технически это две независимые проблемы и чинятся по-разному.

## Почему не нужно делать "живым" всё сразу

Из 100+ активных контрактов в общей таблице подавляющее большинство никогда не станет реальной
сделкой. Держать постоянный живой WS-поток на каждую строку таблицы — дорого по ресурсам и
бессмысленно: 99% этого никогда не понадобится. Общая таблица с текущим циклом обновления
(плюс уже добавленный фильтр 30 минут и дедупликация) вполне достаточна как первичный отбор
"куда вообще смотреть" — не нужно её ускорять.

## Предлагаемое решение: точечный live-режим только для открытой модалки "Расчёт"

1. Когда пользователь открывает модалку "Расчёт" для конкретной пары — модалка на время своего
   открытия подписывается на живой поток именно этих двух конкретных ног (не всей таблицы):
   - Bybit: уже есть WS-канал (`event.ticker.all`), можно фильтровать/переиспользовать для
     конкретного `symbol` без создания нового подключения с нуля.
   - Polymarket: CLOB API поддерживает WS для ордербука — использовать для конкретного `market_id`,
     как уже сделано в `sec_logger.py` для `poly_48s_lag` (там уже есть похожий паттерн подписки
     на конкретный рынок с проверкой свежести).
2. Пока модалка открыта — цифры (коэффициент, подразумеваемая цена, пересчитанный хедж) обновляются
   раз в секунду или чаще, прямо на глазах у пользователя.
3. При закрытии модалки — подписка на эту конкретную пару отключается, чтобы не копить лишние
   открытые соединения без необходимости.

## Почему это дёшево технически (в отличие от "живое всё и всегда")

Один WS-канал на одну открытую в моменте модалку, а не сто каналов на сто строк таблицы
одновременно. Переиспользует уже существующую инфраструктуру (WS-коллекторы, паттерн проверки
свежести из `sec_logger.py`), не требует новой архитектуры с нуля.

## Что не менять

Основной цикл сбора и отображения таблицы (Top Spreads, Cross-Platform) — оставить как есть,
эта идея касается только последнего шага перед принятием решения о реальном клике, не первичного
отбора возможностей.
